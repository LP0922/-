# 2026-08-26：润滑剂1占空比上限由25%提高为35%候选

## 用户要求与证据

用户报告润滑剂1含有大颗粒，窗口已开到p550仍堵在出口，要求提高占空比上限。
检查最新记录确认程序的增占空比指令被25%上限截住：

- `dispense-1000mg-20260826_120719-43a1e3`：80 Hz／22%／p550，
  35.485秒后取消，最后采样154 mg，最大占空比2500；末段多次记录
  `predicted flow is below target; increase duty`，实际占空比始终2500。
- `dispense-1000mg-20260826_120552-52109b`：80 Hz／22%／p500，
  83.781秒后取消，最后采样332 mg，最大占空比同为2500。

这些是取消前采样值，不是稳定终值；日志证明占空比饱和，不能仅凭日志证明颗粒尺寸或堵塞原因。

## 本次修改

只调整润滑剂1专属运行配置中的 `max_duty_permyriad: 2500 → 3500`，
并补充对应警告。35%是下一档实验候选，不是经过验证的启流参数或物料安全阈值。
其含义是允许闭环按流速升到35%，不是一启动就固定输出35%。

- 不修改普通/紧急占空比步长、阶段流率、固定尾料、预测停机或总超时。
- 不启用普通窗口反馈、卡粉恢复调窗或尾段脉冲。
- 不修改共用控制器、服务端、前端、预设代码或其他粉末配置。
- 存储的默认起始点仍是70 Hz／20%／p300。用户手填80 Hz／p550可作为单次覆盖，
  但本次没有把p550定为正式窗口，也没有修改浏览器输入或移动设备。
- 更新研究工作空间中的候选占空比上限，并追加本次实测依据；保留旧历史记录。
- 在首轮候选说明顶部注明本次覆盖和继续测试前提。

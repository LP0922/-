# 想法：让「快加 → 慢加」的切换平滑过渡

> 记录于 2026-10-08。基于 126 条历史遥测的实测轨迹 + `feedback_controller.py` 源码。
> 目的：解决「两段式控制切换时不平滑」的问题，给出可选方案与验证办法。

---

## 零、目标与方法（总览）

**最高目标**：让「快加 → 慢加」的切换**平滑且精准**，并把这一性质推广到 1–10 g 大重量。
衡量口径是四个数（详见第十节）：过渡段 2 s 多喂量、速率恢复目标 ±20% 的时间、慢加段落在目标 ±50% 内的拍占比、慢加段 duty 贴底且仍超速的拍占比。

要达成它，必须**分层**解决四个目标——它们不在同一层，不能混着调参：

| # | 目标 | 现在为什么做不到 | 对应方法 |
|---|---|---|---|
| 1 | **有降速余量**（最要紧） | duty 贴死 1000 的拍占 **18.0%**，其中 **56.1%** 仍超速；窗口位置 **43.7%** 贴死 1000–1100 → **两个旋钮都到行程末端** | **F 时间域 PWM**：贴底后按 N∶1 间歇给料，等效流量再降 N 倍（1000 + N=4 → 等效 250） |
| 2 | **切换不阶跃** | `target_rate` 一档一跳；duty 通道最快 100 万分值/s，追 10 mg/s 要 **10 s** | **D 积分清零 + 迟滞**（先消除二次过冲）→ 有余量后再上 **A 插值带 / B 剩余时间驱动 / E slew 限幅** |
| 3 | **决策不依赖静态表** | 同一 (duty, 窗口) 速率可跨 **100 倍**（晚/粗 0.00–47.50）→ 静态标定表在过渡段**不存在** | **G 质量域规划**（规划剩余质量轨迹 `m_ref(t)`，不问速率）+ **H 一阶惯性尾**（停机改用质量外推） |
| 4 | **从源头少打散** | 高速出粉在物理上打散粉体，切换后实际产率低于预计 | **工艺层**：粗加拆两档 25→18→12，切前插 **2–3 s 再压实驻留**，等粉体密度恢复 |

**必须先做开环标定实验**（闭环日志无法辨识）：**实验 2**「驻留时长标定」（性价比最高——若 2–3 s 驻留即恢复，工艺层就能解决大半）、**实验 3**「PWM 可行性」（确认驱动器接受 duty=0 且不报警）。见第九节。
**实验 1**「阶跃下切辨识」给出过渡段唯一可用的 `rate(t │ duty, 前史)` 曲面。

**落地顺序**：实验 2+3 探路 → **D**（状态层）→ **F**（执行层）= **最小可用组合** → 工艺层 → **G** → **H + A/B**。
核心原则：**先补余量，再谈平滑**。A/B/C 只是有余量前提下的锦上添花。

## 一、现状：切换到底是怎么发生的

代码在 `server/src/powder_sampling_control/dispensing_algorithm/feedback_controller.py`，
核心就是 `decide()` 里这几行（L499–510）：

```python
stage = SETTLE if 连续确认够数 else (COARSE if projected_mass < threshold else FINE)
remaining = target_mass - projected_mass
if stage is COARSE:            target_rate = coarse_rate_mg_s
elif remaining <= precision_start_remaining_mg: target_rate = precision_rate_mg_s
else:                          target_rate = fine_rate_mg_s
```

`threshold = target_mass × coarse_fraction`（0.70 / 0.75 / 0.80，按目标大小取）。

**三个由代码直接决定的事实：**

1. **切换是硬阶跃**：`target_rate` 一档一跳，没有任何过渡。`stage` 一变，目标速率立刻从 25 掉到 15 或 10。
2. **边界用「目标质量的百分比」定义**：`0.75 × target`。于是同一个「慢加阶段」的入口，在小目标时是剩余 50 mg，在 10 g 时是剩余 2500 mg——**绝对剩余量差 50 倍**，过渡的粗细完全随目标漂移。
3. **中间那档几乎不存在**：`fine_rate` 只在 `remaining ∈ (precision_start_remaining_mg, threshold]` 区间生效。以润滑剂1 200 mg 为例，precision 45、threshold 150 → 只剩 **remaining 45–50 mg 这 5 mg 宽**。所以操作员看到的就是「两段」。

**执行端的天花板**（`FeedbackSettings`）：

| 参数 | 值 | 含义 |
|---|---|---|
| `duty_step_per_update` | 50 | 每次最多改 50 万分值 |
| `duty_update_interval_s` | 0.5 | 最快每 0.5 s 改一次 |
| → 等效 duty 变化率 | **100 万分值/s** | 想改 1000 万分值要 **10 s** |
| `duty_gain_per_mg_s` | 100 | 速率差 1 mg/s → 要 100 万分值 |
| `emergency_duty_step_per_update` | 200 / 0.25 s | 过速保护用 |

**结论：目标速率一步跳 10 mg/s，等于要求 duty 变 1000 万分值，而 duty 通道最快也要 10 s 才走得完。**

## 三、根因：三个断点，分别在不同层

| 层 | 断点 | 现象 |
|---|---|---|
| **目标层** | `target_rate` 阶跃 | 目标一步掉 10–20 mg/s |
| **执行层** | duty 靠 PI 以 100 万分值/s 追 | 追不上 → 过冲；或贴到下限 → 停滞 |
| **状态层** | 积分项跨阶段保留、边界无迟滞 | 切换瞬间积分反号 → 再次过冲；阈值附近抖动 |

## 四、方案

### 方案 A（最小改动，建议先做）：把「阶跃点」改成「插值带」

不要新增阶段，只把 `target_rate` 的计算从「查表」改成「按剩余量插值」。
直接复用同文件里 `tail_taper` 已有的 progress 写法（L1059–1069）。

```python
# 过渡带：从 ramp_start 剩余量开始降速，到 ramp_end 降到 slow 档
progress = clamp((ramp_start - remaining) / (ramp_start - ramp_end), 0, 1)
w = progress * progress * (3 - 2 * progress)        # smoothstep，两端导数为 0
target_rate = coarse_rate + (slow_rate - coarse_rate) * w
```

**参数怎么定：** `ramp_start = precision_start_remaining_mg + 60`，`ramp_end = precision_start_remaining_mg`。
按现有 profile 代入：

| 粉末 | coarse | slow | precision_start | 建议 ramp_start |
|---|---|---|---|---|
| 润滑剂1 | 25 | 10 | 45 | **105** |
| 封堵剂1 | 15 | 6 | 50 | 110 |
| 失水剂1/2 | 35 | 14 | 37.5 | 98 |
| 膨润土 / 封堵剂2 | 25 | 10 | 70 | 130 |

带宽 60 mg 的来历：`25 mg/s` 下走 60 mg 约 **2.4 s**，刚好覆盖 duty 通道一个来回的调节时间（0.5 s × 5 次更新）。
带宽太窄（现在的 5 mg ≈ 0.2 s）等于没有过渡。

### 方案 B（更彻底）：改成「按剩余时间」驱动，而不是「按目标百分比」

把切换条件从 `projected_mass < target × 0.75` 改成「**剩余时间** τ = 剩余量 ÷ 当前速率」：

```python
tau = remaining / max(control_rate, 1.0)
w = smoothstep(clamp(tau / T_ramp, 0, 1))          # T_ramp ≈ 3~5 s
target_rate = v_min + (v_max - v_min) * w
```

**为什么这个更好：**

- 过渡时长恒定（永远 ~3–5 s 的减速量），**与目标质量解耦**——解决了「10 g 时过渡带 2500 mg、200 mg 时只有 5 mg」的漂移；
- 减速距离自动适配当前实际流量：流量大就早开始，流量小就晚开始，天然抗粉末差异；
- 不再需要给每个粉末单独算阈值，只需要一个 `T_ramp`。

上面的图就是按这个思路画的。

### 方案 C：duty 前馈（解决「执行层追不上」）

过渡开始时，不要等 PI 慢慢走，直接用「速率 → duty」标定关系把 duty 送到位：

```python
duty_ff = duty_for_rate(target_rate)      # 来自 L0 / profile 的锚点插值
self.duty_permyriad = bounded(duty_ff)    # 只在前馈跳一次，之后 PI 微调
```

- 数据来源：`initial_parameters` / L0 profile 里已有 `(rate, duty, window)` 锚点，可插值；
- 现有 `tail_taper` 已经在做类似的事（用一个 duty ceiling 把占空比往下压），把它从「尾巴 65→8 mg」提前到过渡带即可；
- 收益最大，因为**过渡不平滑的主因就是 duty 追不上，不是目标没规划**。

> ⚠️ **2026-10-08 修正：本方案的前提被推翻了，见第八节。**
> 前馈锚点来自「低速稳定状态标定」出来的 (rate, duty) 表，
> 而实测证明同一 (duty, 窗口) 组合给出的速率可跨 100 倍以上——
> 这张表在过渡段根本不存在。C 应改成「在线辨识 + 质量域」（方案 F/G）。

### 方案 D：状态层收拾干净（低风险、立刻见效）

1. **切换瞬间积分清零**：在 L557–559，`error` 因目标降档突然反号，而 `_integral_error_mg` 还带着旧符号 → 过冲。检测到 `stage` 变化时把积分 clamp 到 0。
2. **加迟滞**：进入慢加用 `ramp_start`，想退回快加要 `remaining > ramp_start + 30`，避免噪声在阈值上反复横跳。
3. **过渡窗冻结**：刚进过渡带的头 1–2 个 duty 周期，只观察质量增益、不动 duty（复用 `flow_hold` 的 probe 机制），避免误判。

### 方案 E：目标速率加 slew-rate limit（兜底）

不管前面怎么改，最后对 `target_rate` 本身限速：

```python
target_rate = clamp(target_rate, prev_target_rate - max_slew*dt, prev_target_rate + max_slew*dt)
```

`max_slew ≈ 5 mg/s²` 即可保证任何情况下都没有阶跃。这是最省事的一道保险。

## 八、方案修正与新增

### 8.1 撤回：方案 C 的「查表前馈」

前馈锚点来自低速稳定状态标定，而 7.1 已证明这张表在过渡段不存在。
**保留**「必须前馈」这个判断，**更换**前馈的来源：改为在线辨识（8.2）。

### 方案 F（关键）：时间域 PWM —— 突破 duty 下限

duty 已经贴死 1000 时，唯一还能降平均流量的手段是**不让它连续给料**：

```python
period, active = N, 1
if (update_index % N) != 0:
    duty_cmd = 0          # 或 min_duty，取决于驱动器是否接受 0
else:
    duty_cmd = duty_permyriad
# 等效平均流量 ≈ 连续给料的 1/N
```

- duty 1000 配 N=4 → 平均等效 250，比现在的最低值再降 4 倍；
- N ∈ 1..8 与 duty ∈ 1000..5000 组合，可覆盖约 40 倍流量范围，**足够补上 7.4 的缺口**；
- 前提是 8.2 的质量域决策——间歇给料会让瞬时 `control_rate` 变得破碎，
  再用「瞬时速率 × 视界」判停必然出错。

### 方案 G：质量域规划（替代速率闭环）

不再问「现在应该多快」，改问「到 t 时刻应该已经累计到多少 mg」：

```python
m_ref = m_switch + (target - m_switch) * (1 - exp(-(now - t_switch) / T))
err   = m_ref - measured_mass
duty += K_i * err                     # 纯积分（或比例+积分）
```

- 对「产率不可预测」天然鲁棒：产率低就自动多给 duty，**不需要知道产率是多少**；
- `T` 就是过渡时间常数，物理含义清楚，取代原来含糊的「ramp 带宽 60 mg」；
- 停机判定同样搬到质量域：`remaining ≤ 预测剩余可加量` 时才停。

### 方案 H：把停机尾量从「速率 × 视界」改成一阶惯性

现在是 `predicted_tail = control_rate × prediction_horizon_s`。
既然速率会随时间漂移（7.1 已证），这个式子必然有系统性偏差：

```python
tail = rate_now * tau * (1 - exp(-t_window / tau))     # 一阶惯性尾
# 或更稳：直接用最近 1–2 s 的实测质量增量线性外推，不依赖速率估计
```

改动最小，收益最直接。

## 九、标定实验协议（闭环日志无法辨识，必须专门做实验）

**为什么必须专门做**：126 条全是闭环数据，duty 是控制器自己选的，
「打散 → 产率变化」与「控制器主动降速」纠缠在一起，从日志里无法解耦。
另外近停机时刻 `control_rate` 本身偏低，7.1 里那些 0.00 的格子有一部分是这个测量偏差造成的。

| 实验 | 做法 | 得到什么 | 成本 |
|---|---|---|---|
| **1 阶跃下切辨识** | 粗加到固定质量点 → duty 一步切到指定值并**开环保持 10 s**（不闭环、不动窗口）→ 记录 mass(t) 求 rate(t)。duty ∈ {1000, 1500, 2000, 3000} × 前史 ∈ {刚从粗加来, 已低速稳定 5 s}，各 3 次 | `rate(t │ duty, 前史)` 曲面——过渡段唯一可用的模型 | ~24 次短 run/粉末 |
| **2 驻留时长标定** | 下切前插入固定 duty 驻留，时长 ∈ {0, 1, 2, 3, 5} s，看「切到低速后 3 s 内平均产率」何时回到稳定值 | 验证「再压实驻留」是否真能让低速配置重新有效 | ~15 次 |
| **3 时间域 PWM 可行性** | duty 固定 1000，N ∈ {1, 2, 3, 4, 6, 8}，各 10 s | 平均流量 / 瞬时波动 / 驱动器是否接受 duty=0 且不报警 | ~6 次 |
| **4 窗口位置下探** | profile 现在把窗口钉在 1000–1450，下限是 100 | 确认 1000 以下是否还有降流效果（无效就直接放弃这条路） | ~6 次 |

实验 1 和 3 是必须的；实验 2 是性价比最高的一招——如果 2–3 s 驻留就能让产率恢复，
那工艺层改动就能解决大半问题，不必先动控制律。

## 十二、一句话总结

问题有三层，不要混在一起：
1. **余量层（最要紧）**：duty 和窗口位置都已到底，仍有 56% 的贴底拍超速 → 必须新增调节维度（时间域 PWM）。
2. **模型层**：同一 (duty, 窗口) 下速率可跨 100 倍，静态标定表不存在 → 决策必须有在线辨识 + 质量域，不能查表。
3. **工艺层**：高速出粉打散粉体是上述两层的物理源头 → 分档降速 + 再压实驻留，让低速配置重新有效。

原来的「插值带 + 前馈」只是第 3 层之上的锦上添花；**先补余量，再谈平滑。**

# 可行性评估：用这 126 条数据迭代加粉算法

**结论：可行，且已经跑出可用的初筛结果。**
但这套离线方法只能回答「**哪个方向值得试**」，不能直接给出最终参数——
落粉尾巴对停机时刻不是线性的，最终必须回到设备上跑 A/B 定论。

下面每条结论都附证据数字，均可由 `tools/` 里的脚本复现。

---

## 一、为什么可行：条件都具备

### 1. 数据完整，没缺项
| 指标 | 数值 |
|---|---|
| 记录条数（表格口径） | **126** |
| 有配置 JSON | 126 / 126 |
| 有逐拍遥测 CSV | **126 / 126** |
| 遥测总拍数 | **33 177**（平均 263 拍/条） |
| 含控制速率 `control_rate_mg_s` | 126 / 126 |
| 含预测落点 `projected_stop_mass_mg` | 126 / 126 |
| 含实际确认数 `stop_confirmation_required` | 126 / 126 |
| 目标质量覆盖 | 200 / 500 / 1000 / 2000 / 3000 / 5000 / 8000 / 10000 mg |

### 2. 停机律可以复现（这是可行性核心）
控制器每次判定只有两个输入：**当拍的状态**（`mass_mg`、`control_rate_mg_s`、
`acceleration_mg_s2`）和**一组常数参数**（`prediction_horizon_s`、`target_offset_mg`、
`confirmation_samples`、`fixed_tail_mass_mg`…）。这些**逐拍全部落盘**，
所以把同一段遥测喂给改过的参数，就能离线复现「那一次会停在哪」。

**校验结果**（`tools/replay_stop.py`，用记录里的原参数回放）：
- 停机点完全一致：**102 / 126 = 81.0%**
- 至少触发止损：**115 / 126 = 91.3%**（11 条不触发，多为安全律提前接管）
- 残差（`final_mass − projected_at_stop`）：中位 **−3.88 mg**，|残差| 中位 **11.67 mg**

### 3. 参数空间里有明确信号
`results/sweep_126.txt` 扫描 `prediction_horizon_s × target_offset_mg`：

| horizon | offset | 中位｜偏差｜ | ≤10 mg | ≤20 mg |
|---|---|---|---|---|
| **0.80** | 4.0 | **8.98 mg** | 55.6% | 81.7% |
| 0.80 | 0.0 | 8.98 mg | 55.6% | 81.0% |
| 1.00（现用） | 0.0 | 11.50 mg | 45.2% | 69.8% |
| 1.50 | 0.0 | 22.99 mg | 34.9% | 47.6% |

单看 horizon 这一维，就能把这批数据的 10 mg 通过率从 **45.2% 抬到 55%+**，
且不同粉末的最优值不同（封堵剂1 要 0.6、膨润土是 1.0）——这正是「按粉末调参」的依据。

## 二、边界：这套方法**不能**做什么

1. **反事实落点是估计，不是实测。**
   推算里用了「新落点 ≈ 新停机点的 projected + 该粉末历史残差中位数」。
   落粉尾巴对停机时刻非线性，所以模拟出的通过率只能**比大小**，不能当真实成绩。
   → 所有候选参数必须回设备跑 A/B（batch_test 通道）确认。

2. **样本很不均。**
   润滑剂1 34 条，而 大分子包被剂 7 条、抑制剂1 9 条。
   按粉末调参需要每档 ≥10 条，小样本粉末先补数据。

3. **混了 4 个算法版本，跨版本比较要当心。**
   | 算法版本 | 条数 |
   |---|---|
   | `predictive-stop-v2` | 70 |
   | `predictive-stop-v3-water-loss-agent-2-fast-tail` | 31 |
   | `predictive-stop-v3-bentonite-fast-tail` | 13 |
   | `predictive-stop-v3-fast-tail` | 12 |

   部分粉末已经在 v3 变体上（膨润土、失水剂2），横向比残差时要分版本看。

4. **只覆盖「成功落最终质量」的记录。**
   此前被删掉的 10 条无效数据、以及运行时崩掉的 run 不在内，
   所以这份统计**不代表设备的真实失败率**，只代表「跑完的这批」。

5. **低频异常（卡粉）样本少。**
   12 条卡粉标注里膨润土连续 4 条最可信，其余多为孤例，不足以训练分类器，只能先做规则。

---

## 三、建议的推进路径

1. **先做 ①（按粉末标定 horizon）+ ②（按粉末残差偏置）**——
   零硬件成本，`tools/` 里已有脚本，能立刻给出每粉末的候选值。
2. **挑 2–3 种粉末回设备跑 A/B**（优先 封堵剂1、失水剂2：样本够、headroom 大），
   用真实落点校准「模拟通过率」的可靠度。
3. **补齐小样本粉末**（抑制剂1 / 大分子包被剂 / 封堵剂2），再考虑 ③ 的尾巴模型改写。

细节见 `IDEAS.md`；字段含义见 `notes/DATA_DICT.md`。
